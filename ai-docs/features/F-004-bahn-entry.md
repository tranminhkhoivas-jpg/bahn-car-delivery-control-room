## Behavior (what the user/visitor/admin sees and can do; edge cases and error states)
Agent area chosen by the user on 2026-10-24: **On the road** (breakdowns/warnings, missed or at-risk ferries, running late, tracking gaps). The agent is built and working in local n8n as a router plus 8 problem workflows (vehicle, journey, destination, tracking, incident, documents, expenses, general). It goes beyond the slides: code checks timing and tracking gaps, searches ferries, trains and flights (dataset quotes plus simulated options) and replacement drivers, and every workflow files one plan with all costs and the customer draft for approval, then runs the approved steps as mocks and wakes again when the buyer answers. Details are in [[F-010-bahn-on-the-road-n8n]]. The control room (part 1) is built by Claude as a fork of the Bahn starter with a Needs a person queue (event trigger, approve/reject, step buttons) on the agent tables: [[F-012-bahn-control-room-site]].

User design direction (2026-10-24): one operator first, then several people concurrently. n8n is the agent engine: inside On the road a router (built) calls one problem workflow per problem type, and they share small tool sub-workflows; a parent router across areas is not built. Agent runs are stateless and reload each case from storage, so many cases run in parallel. Concurrent operators still need explicit case ownership and duplicate-action prevention in the site; the Act workflow already refuses proposals that are no longer pending.

Official n8n docs checked 2026-10-24: tool-level human review can pause an AI Agent before selected tools execute; queue mode uses Redis and workers for execution scale. These are current documented capabilities, not verified features of the installed local version. Sources: https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools and https://docs.n8n.io/deploy/host-n8n/configure-n8n/scaling/enable-queue-mode.

What Bahn asks for (source: `BAHN/context/car-delivery-control-room/PARTICIPANT-BRIEF.md`, the deck and the speaker):
- **Business:** Bahn delivers used cars for dealers with one freelance driver per car, door to door in about 2 days (a truck takes 2 to 4 weeks). The brief says over 25,000 cars and 1,500 drivers this year across Finland, Denmark and Germany, run by about 50 people. The Bahn speaker said a bit over 5,000 cars last month, roughly one pickup or delivery every 5 minutes; the problem is scale, not any single case.
- **Part 1, control room (40% of score):** a place where Bahn operations staff and agents work together. Show only the orders that need a person and why; keep the rest out of the way. For each hidden order, say what was checked ("an order nobody checked is not fine"). Any order readable in seconds: what happened, who said what and when, what the agent did, the next decision. Show who does what, how an agent hands a case to a person and gets it back, and what a person sees when an agent fails, stops or is unsure.
- **Part 2, one real agent for one area:** a language model working in a loop with tools, that a person can talk to. It does cheap work first (read, ask, look up), then finishes or brings a person one clear decision. Suggested areas: pickup readiness by phone; driver travel (small-town Germany to Helsinki: trains, buses, taxi, ferry, flights, hotels; compare and book but stop before purchase); on the road (breakdowns, missed ships, delays); driver support. A team may propose its own area.
- **Reference case (brief and deck slide 5):** red warning light on a Bentley. The agent asks the driver if safe, where, and for a photo; looks up the car (dealer-owned, due in Hamburg tomorrow); then shows a person one decision ("Call the dealer" or "Choose another step"). The agent must not decide to pay for servicing itself.

Rules from the brief:
- The agent never contacts a customer (anyone who pays Bahn) on its own. Drivers and pickup places may be contacted.
- A person approves before the agent changes a booking, a date, a cost or sends a customer message. Asking and looking up need no approval. Build so autonomy can grow as the agent earns trust.
- Everything around the agent may be mocked (phone, ferry prices, map, simulated driver replies).
- The control room is for non-engineers and must not look like a developer tool. Bahn's operations staff are mostly students, not car professionals (speaker's answer in the Q&A).
- Keep all data fictional: no real people, messages or bookings.

## How it works (approach, flow in words, libraries/services used and why)
Approach: n8n workflows for the agent (F-010) with n8n Data Tables as v1 storage (Docker/Postgres absent), plus the control-room site in `BAHN/build/control-room/` (F-012), a starter fork running on in-process PGlite instead of Postgres. Material available to build on:
- **Dataset:** `dataset/data/*.jsonl`, a fictional snapshot at `2026-10-21T09:00:00Z` with 100 orders (12 intake, 12 ready, 11 on market, 18 booked, 24 moving, 21 delivered, 2 cancelled), 46 customers, 167 drivers, 202 messages, 19 alerts, 1,352 operational events, 37 travel quotes, 25 travel reservations, 14 agent proposals on 11 orders, and 5 unmatched support-inbox threads. Seventy orders have no alert, incident, endpoint claim, open work item or open conversation. The data is messy on purpose: a quote is not a booking, an alert is a signal not a diagnosis, a driver message is not a location fix, proposal text is never proof of change, and support-inbox candidate orders are hypotheses.
- **Existing agent actors in the data:** `dispatch-agent` (publishes reviewed offers), `ops-copilot` (case research and draft actions), `travel-agent` (quotes and booking proposals), `monitor-agent` (risk detection and follow-up proposals). Proposals carry status `PENDING_REVIEW`, `APPROVED_AWAITING_EXECUTION`, `EXECUTED`, `REJECTED` or `FAILED`, cited `evidence_refs`, and an execution policy `RECHECK_CURRENT_STATE_BEFORE_WRITE`.
- **Starter:** optional, read-only Next.js 16, React 19, TypeScript, Drizzle and Postgres app with a local S3-compatible attachment store. Pages: lane board, order record, support inbox, customers, drivers, places. `lib/present/attention.ts` derives "needs a person" from open alerts, incidents, work items, conversations, proposals, endpoint claims, custody follow-ups and inbox threads. It has no write actions, agent or permissions. Bahn says its lane board is how people worked so far, not the answer.
- **Model access:** the event gives each participant USD 20 of OpenRouter credit; see [[F-005-n8n-mcp-local]] for the key slot.

An earlier inactive n8n draft, `hackathon BAHN — transport intake template` (workflow ID `ICgtqYUJYW4rYLEq`), still exists in the local n8n instance. It was built from the public teaser before the brief was released and does not fit the brief (it is a form-intake branch, not a control room or a looping agent). It is not part of the entry; delete or ignore it only with the user's say-so.
